## 0. 先说结论（懒人版）

**"代码生成视频"是什么：** 不用 AI 画像素，而是**写一段动画代码，逐帧渲染成图片，再用 ffmpeg 拼成视频**。

**它和 AI 视频模型的分工：**

| | 代码生成 | AI 视频模型（Sora / 可灵 / Agnes） |
|---|---|---|
| 文字 | **永远清晰、绝对准确** | 经常糊、写错字 |
| 改动 | **改一行代码，重渲就行** | 整条重新生成，还不一定一样 |
| 画面 | 精确、可控、可复现 | 靠"猜"像素，会闪烁 |
| 擅长 | 动画、数据可视化、科普片、片头 | 真人、实拍质感、艺术创作 |

**整个工具链只需要两个 npm 包**，不用下 Chromium（用你本机已装的 Chrome）：

```powershell
npm install puppeteer-core ffmpeg-static
```

**性能参考：1920×1080 @30fps，渲染速度大概是实时的 1/5**——60 秒的片子渲了 298 秒。

## 2. 两种生成视频的方式，差别在哪

这是理解整件事的关键，我用大白话讲：

### AI 视频模型：它"猜"像素

你给一段提示词，模型根据训练数据**推断**每一帧该长什么样。

**问题：**
- 它不知道"引力"是什么，只知道"看起来像引力的图"
- 文字是它的弱项——因为它没见过足够多准确的汉字
- 改一点就要重来，而且**每次结果都不一样**

### 代码生成：它"算"像素

你写代码规定"第 100 帧时，这个圆的位置在 (500, 300)，半径 20，透明度 0.8"。

**好处：**
- 每一帧都是**算出来的**，完全确定——同一份代码跑两次，结果**一模一样**
- 文字是浏览器渲染的，**和网页上的字一样清晰**
- 不满意？改代码里的数字，重渲那一帧就行

> 一句话：**AI 是"画"视频，代码是"造了一个能播放视频的程序，然后把运行结果录下来"。**

## 4. 整体架构

```
┌─────────────────┐
│  cosmos.html    │  ← 你写的动画（HTML + Canvas）
│  renderFrame(n) │     定义"第 n 帧画什么"
└────────┬────────┘
         │ 无头 Chrome 逐帧调用 + 截图
         ▼
┌─────────────────┐
│   render.js     │  ← 逐帧渲染器（通用，换主题不用改）
│  截图 → stdin   │
└────────┬────────┘
         │ 管道喂给 ffmpeg
         ▼
┌─────────────────┐
│    ffmpeg       │  ← 合成 MP4
└────────┬────────┘
         ▼
┌─────────────────┐
│  add-audio.js   │  ← 加音轨（可选）
└─────────────────┘
```

**关键设计：HTML 里只负责"画一帧"，渲染循环交给 render.js。**

这样换主题时**只需要改 HTML**，渲染器完全不用动。

## 5. 核心就两个脚本

### 5.1 HTML：定义"第 n 帧画什么"

核心约定——暴露一个 `window.renderFrame(frameIndex)` 函数：

```html
<canvas id="c" width="1920" height="1080"></canvas>
<script>
const canvas = document.getElementById('c');
const ctx = canvas.getContext('2d', { alpha: false });
const W = canvas.width, H = canvas.height;

// 确定性伪随机：同一帧永远同一结果
function mulberry32(a) {
  return function() {
    a |= 0; a = a + 0x6D2B79F5 | 0;
    let t = Math.imul(a ^ a >>> 15, 1 | a);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  };
}

// 星空只生成一次，之后每帧复用（否则星星会乱跳）
const rnd = mulberry32(20261002);
const STARS = [];
for (let i = 0; i < 520; i++) {
  STARS.push({ x: rnd()*W, y: rnd()*H, r: 0.5+rnd()*1.8, ph: rnd()*6.28 });
}

window.renderFrame = function(frame) {
  const t = frame / 30;          // 秒

  // 背景
  ctx.fillStyle = '#06070f';
  ctx.fillRect(0, 0, W, H);

  // 星星（用 t 驱动闪烁，但位置固定）
  for (const s of STARS) {
    ctx.globalAlpha = 0.4 + 0.4 * Math.sin(t * 1.5 + s.ph);
    ctx.fillStyle = '#cfe0ff';
    ctx.beginPath(); ctx.arc(s.x, s.y, s.r, 0, Math.PI*2); ctx.fill();
  }
  ctx.globalAlpha = 1;

  // 文字（关键：这样渲染出来的字和网页一样清晰）
  ctx.fillStyle = '#ffffff';
  ctx.font = '700 120px "Microsoft YaHei", sans-serif';
  ctx.textAlign = 'center';
  ctx.fillText('我们都是星尘，来自宇宙', W/2, H*0.78);
};

window.TOTAL_FRAMES = 60 * 30;
window.READY = true;
</script>
```

> ⚠️ **两个关键点：**
> 1. **随机数必须用固定种子**（`mulberry32(20261002)`），否则每次渲染星星位置都不一样，视频会闪。
> 2. **星星要在外面生成一次**，不能在 `renderFrame` 里重新生成。

### 5.2 render.js：逐帧渲染器

这是整个工具链的核心，**逻辑不复杂但细节多**：

```javascript
const puppeteer = require('puppeteer-core');
const ffmpegPath = require('ffmpeg-static');
const { spawn } = require('child_process');

// 1. 找本机 Chrome（不下载 Chromium，省几百 MB）
function findChrome() {
  const cands = [
    'C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe',
    'C:\\Program Files (x86)\\Microsoft\\Edge\\Application\\msedge.exe',
  ];
  for (const p of cands) if (fs.existsSync(p)) return p;
  throw new Error('找不到 Chrome/Edge');
}

// 2. 启动浏览器
const browser = await puppeteer.launch({
  executablePath: findChrome(),
  headless: 'new',
  args: ['--no-sandbox', '--hide-scrollbars', '--force-device-scale-factor=1'],
});
const page = await browser.newPage();
await page.setViewport({ width: 1920, height: 1080, deviceScaleFactor: 1 });
await page.goto('file:///' + htmlPath + '?fps=30&dur=60');
await page.waitForFunction('window.READY === true');

// 3. 启动 ffmpeg（用管道接收帧，不落盘）
const ff = spawn(ffmpegPath, [
  '-y',
  '-f', 'image2pipe',    // ← 从管道读图片
  '-vcodec', 'png',
  '-r', '30',
  '-i', 'pipe:0',
  '-c:v', 'libx264',
  '-crf', '18',          // 质量（越小越好，18 基本无损）
  '-pix_fmt', 'yuv420p', // ← 兼容性关键
  '-movflags', '+faststart',
  outFile,
], { stdio: ['pipe', 'ignore', 'pipe'] });

// 4. 逐帧循环
for (let i = 0; i < FRAMES; i++) {
  await page.evaluate((f) => window.renderFrame(f), i);
  const buf = await page.screenshot({ type: 'png', optimizeForSpeed: true });
  if (!ff.stdin.write(buf)) {
    await new Promise(r => ff.stdin.once('drain', r));   // 处理背压
  }
}
ff.stdin.end();
```

**跑起来是这样：**

```
[渲染] 规格: 1920x1080 @ 30fps  60s  = 1800 帧
  帧 191/1800  28.7s  预计剩余 242s
  帧 1111/1800 162.7s 预计剩余 101s
  帧 1800/1800 298.0s 预计剩余 0s

[渲染] ✅ 完成: cosmos-v2.mp4
[渲染] 大小: 10.19 MB
```

> 💡 **几个容易忽略的细节：**
> - `-pix_fmt yuv420p` 必须有，否则有些播放器打不开
> - **背压处理**（`ff.stdin.write` 返回 false 时等 drain）——不然 ffmpeg 来不及编码会爆内存
> - `page.evaluate` 调用渲染函数再截图，**不能靠 `requestAnimationFrame`**——那个是实时跑的，逐帧渲染必须能"跳帧"

## 6. 最大的技术难点：黑洞的引力透镜

第一版我做出来的黑洞，用户看完的评价是：**"有点抽象，没引力弯曲的那种感觉"**。

我原来的做法很偷懒：画一个黑圆 + 一圈粒子，再套几个同心圆当"引力场"。**看起来就是个眼睛。**

**用户这句话点得挺准**——我确实是在"画一个像黑洞的东西"，而不是在"算引力"。于是推倒重写。

### 正确的做法：真的算光线偏折

引力透镜的物理是：**背景的光经过大质量天体附近时，路径会被弯折。**

数学上有个简化公式（弱场近似）：

$$\theta_{out} = r + \frac{R_E^2}{r}$$

其中 $R_E$ 是爱因斯坦半径。

**翻译成代码**——背景每颗星的位置都按这个公式偏移：

```javascript
for (const s of LENS_STARS) {
  const dx = s.x, dy = s.y;
  const r = Math.hypot(dx, dy);          // 到黑洞中心的距离

  const bend = (Re * Re) / r;            // 偏折量（越近弯得越狠）
  const k = (r + bend * grow) / r;       // 缩放系数

  const x = cx + dx * k;                 // 偏折后的新位置
  const y = cy + dy * k;

  // 越靠近爱因斯坦半径，光越汇聚 → 越亮
  const near = Math.exp(-Math.abs(r - Re*grow) / (Re*0.40));

  // 切向拉伸：把星点沿环方向拉成弧 ← 这是"被拉弯"的视觉关键
  const ang = Math.atan2(dy, dx);
  const stretch = 1 + 4.2 * near;
  ctx.ellipse(x, y, size*stretch, size*0.78, ang, 0, Math.PI*2);
}
```

**三个改动带来的效果：**

| 改动 | 视觉效果 |
|---|---|
| 位置按 `r + R²/r` 偏移 | 星空在黑洞周围被"吸"成漩涡 |
| 靠近环处增亮（高斯衰减） | 形成明显的**爱因斯坦环** |
| 星点沿切向拉长 | 星点变成**弧线**，而不是圆点 |

顺便把吸积盘也改了：

- **开普勒转动**：角速度 ∝ $r^{-1.5}$，内圈明显比外圈快
- **内热外冷**：内圈白热 → 黄 → 橙 → 暗红
- **远端绕到背后**：`sin(ang) < 0` 的粒子降低透明度

> 💡 经验：**"看起来不对"通常是因为你在画"像什么"，而不是在算"是什么"。**
> 画同心圆当引力场谁都会，但算真实偏折公式，出来的东西一眼就能看出区别。

## 7. 中文字幕：这才是代码生成的主场

前面说过，AI 视频模型做中文字幕是灾难。我给你看差距：

**代码生成的：**
```
引力弯折光线，时间也随之放缓
Gravity bends light, and time itself slows
```
一个字都不糊，标点符号都对。

**我用视频理解模型去"验片"时，它还编造了字幕内容**——它把画面描述得很准，但说字幕写的是"从一个点开始，慢慢形成一个球"，**我的代码里根本没这句话**。

这说明两件事：
1. **代码生成的文字是"真"文字**，AI 模型自己反而认不准
2. **验片不能只信模型的描述**，得自己抽帧看

### 字幕的实现

用一个数组管理时间轴：

```javascript
const LINES = [
  { t0: 0.6,  t1: 8.0,  zh: '从 60 亿公里外回望，地球只是一个光点',
    en: 'Seen from 6 billion km away, Earth is only a pale blue dot',
    label: 'PALE BLUE DOT 暗淡蓝点' },
  // ...
];

function drawSubs(t) {
  for (const L of LINES) {
    if (t < L.t0 || t > L.t1) continue;
    const a = Math.min(seg(t, L.t0, L.t0+0.6), 1 - seg(t, L.t1-0.6, L.t1));  // 淡入淡出
    // 中文主字幕
    glowText(L.zh, W/2, H*0.845, 58, a, { weight: 600 });
    // 英文副字幕
    glowText(L.en, W/2, H*0.845+64, 30, a*0.72, { font: F.en, color: '#c9d4f2' });
    // 左下科学标注
    // ...
    break;
  }
}
```

想要加发光效果就设 `ctx.shadowBlur`——**渲染出来的效果和设计软件里做的差不多**。

## 8. 音频环节，我连续错了三次

画面搞定了，接下来加声音。**用户的要求是"简单音频可以"**——不用搞复杂。

我也不想找外部素材（版权麻烦），决定用 ffmpeg **合成**：

- 低频 pad：55Hz + 82.5Hz（纯五度）+ 36.7Hz
- 空气声：粉红噪声带通滤波
- 转场音：7 个镜头切换点，各一个 880→240Hz 的下坠音

**然后我就开始翻车了。**

### 错误 1：tremolo 滤镜频率超范围

我想让低频音"缓慢起伏"（几十秒一个周期），于是用了 tremolo 滤镜：

```javascript
'[0:a]volume=0.16,tremolo=f=0.06:d=0.45[a0]'
```

报错：

```
Value 0.060000 for parameter 'f' out of range [0.1 - 20000]
```

**tremolo 的 `f` 最低只能 0.1Hz**（也就是最快 10 秒一个周期），我做的是 0.06Hz（约 16.7 秒一个周期），超了。

**解决办法：不用 tremolo，直接用 `aevalsrc` 写振幅调制表达式：**

```javascript
// sin(2π·55t) 是 55Hz 正弦波
// 后面乘的那个是"振幅随时间变化"
const PAD_A = `aevalsrc='(0.09*sin(2*PI*55*t)+0.05*sin(2*PI*82.5*t))
                        *(0.65+0.35*sin(2*PI*0.055*t))
                        *(0.85+0.15*sin(2*PI*0.017*t))':d=60:s=48000`;
```

**顺手复习一下调制：** `sin(2π·0.055t)` 是 0.055Hz 的慢波（约 18 秒一周期），把它加 1 再乘到音频上，音量就会缓慢起伏。

### 错误 2：想当然地写扫频公式

我想做个"下坠音"（频率从 880Hz 掉到 240Hz），很自然地写成：

```javascript
`sin(2*PI*(880-660*(t/0.7))*t)`   // ❌ 错的
```

**这个公式频率不是线性的。** 因为正弦函数的相位是**频率对时间的积分**，不是"频率乘时间"。

正确写法要用**相位积分**：

$$\varphi(t) = 2\pi\left(f_0 t - \frac{k t^2}{2}\right)$$

```javascript
const K = (880 - 240) / 0.7;      // 频率下降速率 (Hz/s)
`sin(2*PI*(880*t - ${K/2}*t*t))`  // ✅ 对
```

> 💡 这个坑挺经典的——**只要涉及"频率随时间变化"，都得用积分**，直接用乘法出来的东西听起来会怪怪的。

### 错误 3：把 filtergraph 语法写进了输入参数

我想给音源起个名字方便引用，于是写：

```javascript
inputArgs.push('-f', 'lavfi', '-i', `${PAD_A}[pa]`);   // ❌ 错的
```

报错：

```
Invalid outpad name 'pa'
```

**`[标签]` 是 filtergraph 里的语法，不能写在 `-i` 的输入描述里。**

而且我还犯了第四个错——**索引算错了。**

### 顺便说错误 4：忘了输入视频占 index 0

ffmpeg 的输入索引是从 0 开始按顺序排的，而我第一个 `-i` 是**输入视频文件**：

```
[0] = 输入视频
[1] = PAD_A
[2] = PAD_B
[3] = 空气声
[4...] = 7 个转场音
```

我照着"音源从 0 开始"写，全都差了一位，报：

```
Stream specifier ':a' matches no streams
```

**改成从 1 开始就好了。**

## 9. 还没做的：更丰富的音效

现在音频是"氛围垫音 + 转场音"。**想再进一步可以：**

- 加解说旁白（需要 TTS，或者自己录）
- 更精细的音效设计（比如黑洞镜头加低频轰鸣）
- 用真实音乐（但要注意版权）

**如果你只是要个"有声音不尴尬"的片子，现在这套够了。**

## 10. 完整流程（直接抄）

```powershell
# 1. 建项目（依赖装在项目里，自包含）
mkdir 我的视频项目 && cd 我的视频项目
npm init -y

# 2. 写你的动画 HTML（定义 window.renderFrame）
#    参考第 5.1 节的模板

# 3. 把 render.js 拷进来（第 5.2 节）

# 4. 渲染
node render.js 我的动画.html --fps 30 --dur 30

# 5. 加音频（可选）
node add-audio.js 输出.mp4
```

**目录结构建议：**

```
项目\

├── 预览\        抽帧 PNG
└── node_modules\
```

## 11. 这套方案的边界（别踩空）

**它擅长的：**
- 片头动画、Logo 动效
- 数据可视化、图表动画
- 科普解说片（配字幕）
- 需要精确文字的任何内容

**它做不了的：**
- 真人、实拍质感
- 复杂 3D 场景（除非上 Three.js，那复杂度翻好几倍）
- "随手生成"——**你得先想清楚要什么**

**性能提醒：**
- 渲染速度约 **实时的 1/5**（60 秒片子渲 5 分钟）
- 依赖约 **103MB**（ffmpeg 二进制占大头，79MB）
- 4K 会慢很多，1080p 是甜点

## 12. 最后说两句

做完这支片子，我最大的感受是：

**"AI 生成"和"代码生成"不是竞争关系，是工具箱里的两把不同的锤子。**

- 要真人的脸、实拍的质感 → **用 AI 视频模型**
- 要精确的文字、可控的动画、能反复微调 → **用代码**

那支宇宙短片里的"我们都是星尘"，如果交给 AI 视频模型做，出来的大概率是一堆糊掉的方块字；用代码做，**它就是一行清晰的 58px 微软雅黑**。

**所以别被"AI 能生成视频了"这句话框住。** 有时候最"笨"的办法——老老实实写代码算每一帧——反而是唯一能把事做对的办法。
