## 先说结论（懒人版）

1. **Ombre Brain 不是"装进 App 的东西"** —— 它是个独立跑着的服务，App 只是客户端。想清楚这一点，后面全顺了。
2. 用户拍板**买服务器**（不跑电脑、不跑手机），理由是要"在外面也能用"。阿里云经济型 e，2核2G，**¥99/年**。
3. **国内服务器直连 Docker Hub 是不通的** —— 必须配镜像源。这一步不知道会卡到怀疑人生。
4. 镜像下到 304MB 卡死过一次（镜像源掐连接），**加超时重试**才下完；下完**核对了官方 digest**，确认没被动手脚。
5. 服务自带的默认配置里有**两个坑**：模型名是已经废弃的 `deepseek-chat`、思考模式开着会把打标结果截断。都得手动改。

## 一、起因：一句话听岔了

用户最初的诉求是：

> "我打算在 operit ai 部署 mcp 然后这个项目，我是纯小白，应该怎么做从哪里开始"

这里有个概念要先掰开：**Ombre Brain 不是"要装进 Operit 里的插件"。**

它是一套独立运行的服务（Python + SQLite，记忆存成一堆 Markdown 文件），Operit 只是**通过 MCP 协议连过去**的客户端之一。所以真正要回答的问题不是"怎么装进 Operit"，而是：

**这个服务跑在哪台机器上？**

想清楚这个，后面所有事都顺了。想不清楚，就会一直在 Operit 的设置界面里打转。

---

## 二、两个查证，都推翻了"我以为"

### ① 模型名字：用户当场纠正了我

我在第一版方案里写"DeepSeek 有 `deepseek-chat` 和 `deepseek-reasoner` 两个模型"。

用户回了一句：

> "目前不是 flash，和 pro，模型吗？"

我去查了官方价格页 —— **他说得对**。现在是 `deepseek-flash`（DeepSeek-V4.1-Flash）和 `deepseek-v4-pro`，`deepseek-chat` 那个名字**已经不存在了**。

这件事的后果比看起来严重：**Ombre Brain 自带的默认配置里写的就是 `model: "deepseek-chat"`**。如果照默认配置直接用，一存记忆就会报错。

👉 所以后面改配置时，这一条是必改项。

### ② DeepSeek 没有向量化接口

这一条更隐蔽。Ombre Brain 干活要**两个**模型：

| 干什么 | 用谁 | 说明 |
|---|---|---|
| **存**记忆（把聊天压缩成一条带标签的笔记） | DeepSeek `deepseek-flash` | 文本模型 |
| **找**记忆（按意思检索，不是按字面） | **向量模型** | 把每句话变成一串数字，意思近的数字就挨得近 |

而**DeepSeek 压根不卖第二种**。它的模型列表里只有对话模型，没有 embedding 接口。

所以光有 DeepSeek key 不够，还得再找一家。最后选了**硅基流动**的 `BAAI/bge-m3`（免费）。

> 💡 这个"存和找是两个不同的模型"的分工，是整件事里最容易搞混的地方。
> 用户一开始也问"能不能服务器干脆起个本地小模型也一样" —— 见下面第四节。

## 三、选型：跑在哪台机器上

摆在面前三条路：

| 方案 | 优点 | 缺点 |
|---|---|---|
| 跑在**用户自己的电脑**上 | 免费、我全权操作 | 关机 / 重装就断，而且那是台折腾机，不稳 |
| 跑在**手机里**（Operit 自带 Ubuntu） | 出门也能用、不依赖电脑 | 要在手机上装 Python 环境，卡住不好救 |
| 跑在**独立服务器**上 | 24 小时在线、崩了随时重装 | 要花钱 |

**用户拍板：买服务器。** 他的原话是"最好便宜，然后可以在外面也可用"。

价格我给了一个横向参考（当时查的）：海外年付 $20–50（RackNerd / CloudCone 这类）、搬瓦工 $49.99/年、国内轻量服务器新用户常年有 ¥99–199/年的 2核2G。

**用户最后选的是阿里云 ECS 经济型 e，2核2G / 40G 盘 / 3M 带宽，¥99/年。**

---

## 四、一个先回答掉的问题：为什么不用本地向量模型

用户中途问过：

> "能不能服务器干脆起个本地小模型也一样"

我在服务器上实测了内存：

```
内存总共      1736 MB
服务跑着时可用  1024 MB
```

而 `bge-m3` 这个向量模型加载后**要常驻 2–3GB** —— 差一倍还多。硬跑的后果是系统疯狂用 swap、检索从 0.5 秒变成好几秒、还可能被 OOM 杀掉。

**结论：不用本地，用云端那个免费的。**

> 但这里有个诚实的补充：**本地模型唯一真正的价值是隐私** —— 用云端意味着记忆文本要发到第三方去算向量。
> 对这台机器来说，省下的那点事换不来内存不够的麻烦。真要较真隐私，正确做法是把服务器内存升到 4G 以上，而不是硬塞。

## 五、买服务器：控制台的字段名和教程对不上

这一段主要是**用户在操作**，我在旁边给步骤。踩的坑挺典型：

我按记忆里的说法让他"填授权对象 0.0.0.0/0、端口范围 18001/18001"，
结果新版控制台的字段**改名字了**：

| 老叫法 | 新版叫法 |
|---|---|
| 授权对象 | **访问来源** |
| 端口范围 | **访问目的（本实例）** |

用户当场发了个截图加三个问号。对着截图重说一遍就过了。

> 教训：**给小白写操作步骤，最好让他先截图**，别照着自己记忆里的界面描述。

## 六、装 Docker：一条"所有源都 404"的路

按常规做法，我加了 Docker 官方的 `docker-ce` 源（走阿里云镜像）。结果：

```
Err: File has unexpected size (89199 != 89376). Mirror sync in progress?
```

**阿里云的 docker-ce 源当天正在同步**，索引文件和实际文件对不上。

于是换清华源 —— 索引对了，但安装包 **404**：

```
Err: containerd.io_2.4.1 ... 404 Not Found
Err: docker-ce_29.9.0 ... 404 Not Found
```

清华那边也是**索引同步了、包还没同步完**。

最后绕开整个 docker-ce 体系，用 **Ubuntu 自带源**里的：

```
docker.io                   29.1.3-0ubuntu3~22.04.2
docker-compose-v2           2.40.3+ds1-0ubuntu1~22.04.1
```

版本一点都不旧，而且走的是阿里云内网镜像（实测 **59.5 MB/s**），几秒装完。

> 💡 这一步的启发：**"官方的、最新的"不一定是最顺的路**。
> 发行版自带的包经常更省事，尤其在国内网络环境下。

## 七、拉镜像：500MB 的三段式

### 第一段：发现根本连不上 Docker Hub

```
registry-1.docker.io: 000 (10.2 秒超时)
```

**国内服务器直连 Docker Hub 不通。** 只能用镜像源。我探测了一圈，最后选的 `docker.1panel.live`（实测能拿到镜像清单）。

### 第二段：下到一半卡死

500MB 的镜像，3M 带宽跑满也要 20 多分钟。跑到 **304MB 时卡住了** ——

```
8 秒内收到 9 KB
```

镜像源**把连接掐了**。Docker 的拉取不会自动续，就那么挂着。

解决办法是加超时重试：

```bash
for i in 1 2 3 4; do
  if timeout 600 docker compose pull; then break; fi
  sleep 5
done
```

**关键是：已经下完的分层会保留**，重试只补没下完的。所以第二次、第三次能接着往前推。

### 第三段：下完必须核对指纹

镜像来自第三方镜像源，理论上存在被动手脚的可能。所以下完我做了件事 —— 拿服务器的镜像 digest 和 Docker Hub 官方 API 报的对比：

```
本机: p0luz/ombre-brain@sha256:25258dadd0000fec7772ebf86a8c4621b8afe0f4f121f34ca114088c67313967
官方: sha256:25258dadd0000fec7772ebf86a8c4621b8afe0f4f121f34ca114088c67313967
```

**一致。** 镜像没被改过。

> 这一步不做也不影响使用，但既然是从非官方源拉的，核一下心里踏实。

## 八、改配置：三个必改项

服务起来之后，翻它的默认配置文件，发现三处必须改：

| 配置项 | 默认值 | 改成 | 为什么 |
|---|---|---|---|
| `dehydration.model` | `deepseek-chat` | `deepseek-flash` | 旧名字已经不存在了，不改一存记忆就报错 |
| `dehydration.max_tokens` | `1024` | `4096` | 太小的话返回的 JSON 会被截断，**所有记忆都被标成「未分类」** |
| `extra_body.thinking.type` | （未设置＝开） | `disabled` | DeepSeek 默认开思考模式，**思考 token 会占掉输出预算**，同样导致截断 |

第三条值得多说一句：**DeepSeek 的思考模式默认是开的，而且是 `high` 强度。**

Ombre Brain 让模型干的是"给这段内容分类打标签"这种结构化输出，不需要推理。思考模式在后台先输出一大段思维链，这段**也算在 `max_tokens` 里**，很容易把真正的 JSON 挤掉。

官方文档里控制参数是：

```json
{"thinking": {"type": "enabled/disabled"}}
```

（OpenAI 格式下要放在 `extra_body` 里。）

## 九、实测：整条链路跑通

配置改完，做了次端到端实测 —— 真写一条记忆进去，再搜出来，再删掉：

```
=== 1. 写一条测试记忆 hold(test_data=True) ===
    耗时 2.1 秒
    返回: 新建→555ff54efe6b 编程,AI

=== 2. 语义搜索 breath_search 找回来 ===
    耗时 0.7 秒
    返回: [bucket_id:555ff54efe6b] ...

=== 3. 硬删除测试桶 ===
    返回: 已永久删除测试桶: 555ff54efe6b
```

服务端日志里的诊断信息更关键：

```
'semantic_available': True,
'vector_candidates': 1,
'vector_top': [{'bucket_id': '...', 'score': 0.751807}],
'engine': {'model': 'BAAI/bge-m3', 'vector_dim': 1024, 'embedding_count': 1},
'outbox': {'pending': 0, 'retrying': 0, 'last_error': ''}
```

**向量 1024 维、语义通道真的在工作、队列没有积压、没有报错。** 到这一步，服务端就算成了。

## 这一篇里踩过的坑（速查）

| 现象 | 看起来像 | 实际是 |
|---|---|---|
| `File has unexpected size ... Mirror sync in progress?` | 源挂了 | **源正在同步**，换一个或等一会儿 |
| 换了源还是 `404 Not Found` | 包不存在 | **索引同步了、包还没同步完** |
| `registry-1.docker.io` 超时 | 网络坏了 | **国内直连 Docker Hub 本来就不通**，得用镜像源 |
| 下到 304MB 就 8 秒收 9KB | 镜像太大 | **镜像源掐了连接**，加超时重试能续 |
| 记忆全被标成「未分类」 | 打标模型太笨 | **max_tokens 太小 + 思考 token 占了预算** |
