## 一、先说结论（懒人版）

1. **"两只"不是 bug，是插件的默认配置。** 它有一个 `display` 字段决定宠物出现在哪，
   **默认值是 `both`** —— 也就是同一只**在"网页外壳"和"桌面浮窗外壳"里各渲染一份**。
2. **四个值**：`web` 只在浏览器页面里 / `desktop` 只在桌面浮窗 / `both` 两边都有 / `none` 都不显示。
3. **改法**：插件的用户配置文件（默认不存在）里写一段，把 `display` 改成 `desktop`；
   **生效方式是右键宠物 →「重载配置」**，或者重启宿主。删掉那个文件 = 完全恢复默认。
4. **烧 token 吗？只有一个功能烧。** 宠物本体（动画/拖拽/走路）、**工作状态联动**（它跟着你的任务换动作）、
   余额展示 —— **全都不调模型**。**只有「碎碎念」会**：默认**开着**，周期**300 秒**，
   也就是**每 5 分钟调一次模型**。
5. **想零消耗就关一个开关**：配置里 `whisperEnabled: false`；或者把周期从 300 秒拉长到 1800 秒。

## 二、"两只"的真相是 `display: both`

用户的原话是「我下了个桌面宠物，为毛会有两个」。

按惯例先读安装记录 —— 发现那份笔记停在半个月前，**这个插件和另一个新插件都没记**。
于是直接去翻插件的包目录，把它的 `package.json`、自带默认配置和 README 都读了一遍。

答案在自带默认配置里：

```jsonc
"pets": [
  {
    "name": "蓝毛小女仆",
    "id": "main",
    "size": 462,
    "display": "both",        // ← 就是这一行
    "position": { "corner": "top-right", "marginX": 24, "marginY": 100 }
  }
]
```

而 `display` 的四个可能值，配置注释里写得很清楚：

| 值 | 宠物出现在哪 |
|---|---|
| `web` | 只在浏览器页面里（overlay） |
| `desktop` | 只在桌面浮窗（Electron 透明窗） |
| `both` | **两边都有 ← 默认** |
| `none` | 都不显示（等于关掉这只） |

README 里还有一句话把这件事说死了：

> 页面配置的显示位置由 `display` 字段决定，两端宠物内容**只可能一致**，
> 不会出现"一个有另一个没有"。

**所以用户看到的"两只"，是同一只在两个外壳里各渲染了一份。**

### 怎么改

用户配置文件是：

```
<用户目录>/.dsh/dsh-pet/main-config.jsonc
```

**默认是不存在的**（说明它一直在用插件自带的默认值）。这个文件我实测确认过：
目录都不存在，宠物跑起来之后也没有自动生成。

⚠️ **有个坑得先说**：这个插件的配置合并口径是「**顶层字段整段替换**」——
写了 `pets` 就得把整只宠物的字段写全，**缺的子键不会从内置默认里补回来**。
所以最安全的写法是**只写 `pets` 这一段**，别的一个字不碰：

```jsonc
{
  "pets": [
    {
      "name": "蓝毛小女仆",
      "id": "main",
      "size": 462,
      "balanceEnabled": true,
      "whisperEnabled": true,
      "workStatusEnabled": true,
      "fixedEnabled": false,
      "display": "desktop",      // ← 改成只留桌面那只
      "position": { "corner": "top-right", "marginX": 24, "marginY": 100 }
    }
  ]
}
```

**生效方式**（两种随便挑）：**右键宠物 →「重载配置」**（这是桌面端专有的菜单项，
会重建全部桌宠窗口），或者重启宿主。

**删掉那个文件 = 完全恢复默认。**

> 顺带说：这个插件还有一个**独立模式**（`npx <插件名>-standalone`）——
> 不开宿主、直接自己跑一只，会起自己的 Electron helper。
> **那是"两只"的另一个可能来源。** 我查了进程，只看到一个 electron（是桌面 helper），
> 所以你这次的原因是 `both`，不是独立模式。

## 三、烧不烧 token：只有一个功能烧

这个问题是用户主动问的，问得很对 —— **因为这类"陪伴型"插件最容易在你不知道的地方悄悄计费。**

我把它的功能一个个对了一遍：

| 功能 | 烧 token 吗 | 依据 |
|---|---|---|
| 宠物本体（动画/拖拽/走路/点击回应） | ❌ 不烧 | 纯本地动画资源 |
| **工作状态联动**（它跟着你的任务换动作） | ❌ 不烧 | README 原话：「**仅监听，不调用模型**」 |
| 余额展示 | ❌ 不烧 | 那是查账户余额，不是生成 |
| **碎碎念** | ✅ **烧** | **唯一的后台消耗** |
| 右键「对话」 | ✅ 烧 | 但那是你主动找它聊，按次算 |

### 碎碎念烧多少

README 原话：

> 按 `eventsRefreshSec.whisper` 周期（**默认 300 秒**）调用当前会话所用的模型生成

算一下：

- **每 5 分钟一次** → **一天 288 次**
- 每次送过去的是：人设提示词 + 一句名字声明 + 一张配图的描述（**不带对话上下文**），
  大概 250~400 token 输入 + 30~50 token 输出
- 合起来大约 **9 万 ~ 13 万 token / 一天**

⚠️ **这是按提示词长度估的，不是实测** —— 装上才十来分钟，量不出来。
**想看真实数字，去服务商后台看今天的用量，跟前一天对比最准。**

还有一个值得知道的细节：**它用的是"当前对话的模型和 key"**
（配置里那个模型字段留空 = 跟随当前会话）。所以它花的是你平时在用的那个 key。

### 怎么办

**想零后台消耗**，把那一只宠物的碎碎念关掉：

```jsonc
"whisperEnabled": false
```

关掉之后它就不自己冒泡了，**但宠物本体、动作、工作状态联动一切照常，而且后台零 token**。

**想留着但省一点**，把周期拉长：

```jsonc
"eventsRefreshSec": { "whisper": 1800 }    // 半小时一次，省 6 倍
```

> 另外 README 里还有一条，如果你以后换本地模型要注意：
> 「本地 LLM 单并发时，**后台碎碎念会顶掉正在跑的任务的 KV cache**」——
> 跟宿主开多个子代理是同一个毛病。**用云端 API 的话只是花钱，不抢资源。**
