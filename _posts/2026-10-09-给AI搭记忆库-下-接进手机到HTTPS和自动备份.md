## 先说结论（懒人版）

1. **在 Operit 里配 MCP，别在手机上瞎试**。三次失败全是靠**服务器日志**一眼定位的：一看请求打到哪、返回什么状态码，就知道错在哪。
2. **Cloudflare 的 Zero Trust 要国际信用卡**，国内基本过不去 —— 但**不用它也能建隧道**（本地管理隧道，纯命令行）。
3. **上了隧道之后，公网端口就可以全关了。** 服务从"全网可扫"变成"扫都扫不到"。
4. **GitHub 备份只推 `.md` 记忆和原文证据，不推配置文件** —— 所以 API key 不会泄露。但**仓库必须私有**。
5. **最有价值的一条教训**：那个报"分支不存在"的错误，真实原因是**权限不够**。**报错文本会骗人，要往下查一层。**

## 一、接进 Operit：连了三次才成

服务端跑通了，接下来要在手机上把它接上。Operit 里有「导入或连接 MCP 服务」的入口，选「远程」，填地址和 Token。

然后连着踩了三个坑。

### 坑① 连接按钮一直是灰的

用户发来截图：「我输入了结果连接按钮没亮」。

我去翻了 Operit 的源码（它是开源的），找到那个按钮的启用条件：

```kotlin
enabled = ... && remoteEndpointInput.isNotBlank() && pluginNameInput.isNotBlank()
```

**主机地址非空「且」名称非空。** 那个「名称」输入框在对话框下面，要滚动才看得见 —— 用户压根没注意到还有个名称要填。

### 坑② 405 Method Not Allowed

名称填上、按钮亮了、点连接 —— 连不上。

这时候**服务器日志救了我**：

```
POST / HTTP/1.1   →   405 Method Not Allowed
```

它请求的是**根路径 `/`**，不是 `/mcp`。地址栏里少了末尾那段路径。

> 💡 这一步的意义：手机上只显示"连接失败"，服务器上直接告诉你是**打错了地方**。
> 有服务器可看日志，是自建服务相对"用别人的云服务"最大的优势之一。

### 坑③ 401，Token 少了一截

补上 `/mcp` 再试，这次日志显示：

```
GET /mcp HTTP/1.1   →   401 Unauthorized
```

401 就是**鉴权没过**。我让用户把 Token 那一栏点开、光标移到最前面看一眼 —— 果然，**开头少了 10 个字符**。粘贴的时候断了一截。

补齐之后：

```
POST /mcp 200 → POST /mcp 202 → POST /mcp 200 → GET /mcp 200
Processing request of type ListToolsRequest
```

**16 个工具全部拉到了，服务端日志一条错都没有。** 接进去了。

> 补充一句：这一切全程走的是**手机 5G**，不是家里的 Wi-Fi —— 相当于顺手验证了"在外面也能用"。

## 二、把 Operit 里原来的记忆搬过去

用户之前的记忆存在 Operit 自带的记忆库里。他问：

> "比如 Operit 自带的记忆，能让 ai 自己导入吗"

能。我去查了 Operit 的记忆 API 文档，它支持：

```
Tools.Memory.query('*')     // 传 * 返回【所有】记忆
```

而且带**快照分页**（`snapshotId`）——超过 20 条可以反复翻页，不会重复也不会漏。

所以做法是：让 AI **自己读自己的记忆，再用记忆库的写入工具写进去**。给它的指令就一段话：

```
1. 先用 Tools.Memory.query('*', undefined, 20) 列出你的记忆，记住返回的 snapshotId
2. 用同一个 snapshotId 继续翻页，直到列完
3. 对每一条，用 hold 写进 Ombre Brain —— 标题和正文照搬，不要改写、不要总结
4. 每搬完 10 条跟我报一次数
```

**结果：47 条全进来了。** 每条都被自动打上了主题标签和情感坐标，不用手动整理。

> ⚠️ 一个建议：**搬之前先让它把清单列给你看**。
> App 自带的记忆里通常有一半是测试内容或过期信息，搬进去还得清。

## 三、上 HTTPS：一条被信用卡挡住的路，和一条绕过去的路

### 为什么非上不可

到这里为止，手机连服务器走的是**明文 HTTP**：

```
http://<服务器IP>:18001/mcp
```

意思是：**Token 和记忆内容在网络上都是裸的**。家庭宽带和 5G 上被截包的概率不高，但不是零 —— 既然要拿它长期存东西，这条链就该是加密的。

另外，18001 这个端口是**对全网开放**的，扫描器一定会扫到（虽然没 Token 进不去）。

### 第一反应：Cloudflare 隧道 —— 结果被卡住了

Cloudflare 有个免费服务叫 **Zero Trust 隧道**：在服务器上跑一个 `cloudflared`，它主动往外连到 Cloudflare，外部访问走 Cloudflare 的域名进来。**服务器不用开任何公网端口**，全程 HTTPS。

但用户去开 Zero Trust 的时候卡住了：

> "不行，这个 zero 要银行卡我没有"

**Zero Trust 后台要求绑支付方式**，国内没有国际信用卡基本过不去。

### 转折：不用 Zero Trust 也能建隧道

我去翻 Cloudflare 的文档，发现它其实有**两套**隧道管理方式：

| | 远程管理隧道 | **本地管理隧道** |
|---|---|---|
| 在哪建 | Zero Trust 后台 | **命令行** |
| 授权方式 | 后台生成 token | **浏览器授权一次，拿凭据文件** |
| 要不要卡 | **要** | **不要** |

本地管理隧道的思路很朴素：**在一台有浏览器的机器上授权一次，把凭据拷到服务器，之后全靠命令行。**

具体这么做：

**1. 在有浏览器的电脑上授权**

```bash
cloudflared tunnel login
```

它会打印一个链接，在浏览器里打开、登录 Cloudflare、选中域名、点 Authorize。
授权完，凭据（`cert.pem`）就落到本机了。

> 一个细节：那个回调地址是 `login.cloudflareaccess.org`，**不是 localhost** ——
> 所以浏览器在哪台机器上都行，不用非得登在服务器上。

> 另一个细节：`cloudflared` 默认想写 `C:\Users\<用户名>\.cloudflared\`，被沙箱挡了（`Access is denied`）。
> 解决办法是把 `USERPROFILE` 环境变量指到工作区目录再跑，凭据就落在工作区里了。

**2. 建隧道，把凭据拷到服务器**

```bash
cloudflared tunnel create ombre-brain
# 得到 <隧道ID>.json 凭据文件 + cert.pem，两个一起拷到服务器 /etc/cloudflared/
```

**3. 服务器上写配置**

```yaml
tunnel: <隧道ID>
credentials-file: /etc/cloudflared/<隧道ID>.json
protocol: http2
ingress:
  - hostname: ob.<你的域名>
    service: http://127.0.0.1:18001
  - service: http_status:404
```

**4. 加 DNS、装成服务**

```bash
cloudflared tunnel route dns ombre-brain ob.<你的域名>   # 自动在 Cloudflare 建 CNAME
cloudflared service install                            # 装成 systemd 服务
systemctl enable --now cloudflared
```

启动时它会自己跑一遍连通性预检，全 PASS 才算好：

```
UDP Connectivity  region1.v2.argotunnel.com  PASS  QUIC connection successful
TCP Connectivity  region1.v2.argotunnel.com  PASS  HTTP/2 connection successful
Cloudflare API    api.cloudflare.com:443     PASS  API is reachable
SUMMARY: Environment is healthy.
```

**5. 验证**

```
https://ob.<你的域名>/health          → 200 {"status":"ok"}
https://ob.<你的域名>/mcp  initialize → 200
tools/list                            → 18 个工具
不带 Token                            → 401 ✓
```

### 最后一步：把公网端口删掉

HTTPS 通了之后，去云控制台的安全组里，把 18001 那条入方向规则**删掉**。

再测一遍：

```
从外面探测 18001  →  超时（扫不到了）
https://ob.<你的域名>  →  照样 200
```

**服务活着，但公网扫不到它。** 这才算真正做完。

## 四、GitHub 自动备份：报错骗了我好几轮

最后一件：**记忆只有服务器上一份，硬盘坏了就全没**。用户一开始拒绝了 GitHub 备份（"私有仓库似乎要钱"—— 其实**私有仓库是免费的**，2019 年起就不限数量），后来还是决定做。

### 先确认它到底推什么

在看配置界面之前，我先去翻了它的源码。`github_sync.py` 开头写得很清楚：

```
- 同步 buckets_dir 下的 .md 记忆、_sources 原文证据和经校验的 You 事务快照
- embeddings.db 不上传（二进制，可由 ... 重算）
```

再看代码，路径过滤是 `endswith(".md")`。

**结论：配置文件（`config.yaml`、`.env`）和向量库都不推** —— 所以里面那两把 API key 不会泄露。

但**原文证据会推**（`_sources/`，比整理后的记忆正文更完整），所以 —— **仓库必须是私有的**。

### 然后是连环坑

**坑① 仓库名只填了一半**

配置界面的仓库栏写着 `owner/repo-name`，用户只填了仓库名，没填用户名。日志里：

```
GET https://api.github.com/repos/<仓库名>   →   404
```

要填 `<用户名>/<仓库名>`。

**坑② 改了还是不行，而且报错开始骗人**

改成全名之后，报错变了：

```
[github_sync] sync failed: 分支 main 不存在，请先在 GitHub 上创建该分支
```

但用户截图给我看那个仓库 —— **`main` 分支明明在，还有一个 commit**。

于是我去看它到底请求了什么：

```
GET https://api.github.com/repos/<用户名>/<仓库名>/git/ref/heads/main  → 404
```

**问题不在"分支"，在于服务器根本看不见这个仓库。** 我拿它存的 token 直接打了一下：

```
GET /repos/<用户名>/<仓库名>   →   Not Found
```

**GitHub 对"没有权限的私有仓库"一律返回 404**，不区分"不存在"和"你没权限"。而 Ombre Brain 的同步代码没有区分这两种 404，于是把"看不见仓库"报成了"分支不存在"。

> 💡 **这是整篇里最值钱的一条经验。**
> 报错文本只反映**它自己以为**的问题。当报错和事实（截图里明明有 main 分支）冲突时，
> **要往下查一层** —— 直接拿凭据去敲底层 API，看真实状态码。

**坑③ token 授权选错了仓库**

翻 token 配置页截图，发现「Repository access」选的是 "Only select repositories"，然后**勾错了仓库** —— 勾成了一个公开仓库，跟目标仓库没关系。

**坑④ 权限没加**

同一个页面下方「Permissions」写着 `No repository permissions added yet` —— 压根没加权限。必须手动加 **Contents: Read and write**。

**坑⑤ 仓库名里的中文被吃掉了**

用户建仓库时填的中文名，被 GitHub **静默剥掉**，只剩前面的字母和一个横杠（所以那个仓库名结尾带个横杠 —— 不是笔误，是中文被吃了）。

### 最终成功

全部改对之后，日志里是一条完整的提交链：

```
GET  /repos/<用户名>/<仓库名>                → 200 OK     读仓库
GET  /git/ref/heads/main               → 200 OK     读分支
GET  /git/commits/<sha>                → 200 OK     读现有提交
POST /git/blobs                        → 201 Created  上传文件内容
POST /git/trees                        → 201 Created  建目录树
POST /git/commits                      → 201 Created  建提交
PATCH /git/refs/heads/main             → 200 OK      更新分支
```

```
提交信息：Ombre Brain sync — 2026-10-09 12:26 UTC (63 files)
仓库内容：ombre/ 目录下 64 个文件
```

**63 个文件一次推成功，之后每 24 小时自动跑一次。**

## 这一篇里踩过的坑（速查）

| 现象 | 看起来像 | 实际是 |
|---|---|---|
| Operit「连接」按钮灰着 | 输入格式不对 | **「名称」栏没填**（那个框在下面，要滚动） |
| Operit 报连接失败 | 网络/地址错 | 服务器日志显示 **`POST /` 打到了根路径**，URL 少 `/mcp` |
| `/mcp` 返回 401 | Token 过期 | **粘贴时断了一截**，开头少了 10 个字符 |
| Zero Trust 打不开 | 账号有问题 | **它要绑国际信用卡**，换本地管理隧道 |
| `cloudflared login` 报 `Access is denied` | 没权限 | 它要写用户目录，**被沙箱挡**，改 `USERPROFILE` |
| 备份报「仓库不存在」 | 仓库名写错 | 可能只是**只填了仓库名、没填用户名** |
| 备份报**「分支 main 不存在」** | 分支真没了 | **报错在骗你** —— 真实原因是 token 看不见这个私有仓库 |
| token 明明"选了仓库" | 配置生效了 | **选择器点错成了别的仓库** |
| 仓库名跟预期不一样 | 自己记错了 | **建仓库时填的中文被 GitHub 剥掉了** |

## 最后说两句

这一天最深的体会不是"搭成了什么"，而是**中间那些报错全都在指向错误的方向**：

- 说"仓库不存在" → 其实是没权限
- 说"分支不存在" → 其实还是没权限
- 说"连接失败" → 其实是 URL 少了路径
- 说"按钮点不动" → 其实是下面有个框没填

**所以自建服务的核心能力不是"会不会敲命令"，是"能不能看到真相"。**

这一天的救星一直是**服务器日志** —— 手机上只告诉你"失败了"，服务器上写着"你打的是 `POST /`，我返回了 405"。
