<h2 id="ch1">1. 为什么要签名</h2>

你写好了一个 App，发给我。我怎么知道这个 APK 真的是你发的、中间没被别人改了？

签名就是"盖个章"。

就像你寄快递，收件人看到封口没拆过就知道没被调包。Android 系统安装 APK 时会检查这个章——章对得上，说明是原装，让装；对不上或没章，拒绝安装。

两个作用：

1. **防篡改**——App 发布后，有人改了里面的代码再发出去，签名就变了，系统不认
2. **保数据**——同一个 App 的更新版本，签名一样才能覆盖安装，用户数据不丢。签名变了就得卸载重装，聊天记录全没

<h2 id="ch2">2. 三个东西：keystore、alias、密码</h2>

签名就靠三个东西，缺一不可：

| 词 | 原词 | 大白话 | 长什么样 |
|------|------|------|------|
| 密钥库 | keystore | 一个保险箱文件 | `your-app.keystore`（约 3KB） |
| 别名 | alias | 保险箱里一把钥匙的名字 | `myapp`（自己起的） |
| 密码 | password | 开保险箱的密码 | `your_password`（自己设的，≥6 位） |

一个 keystore 能存多把钥匙（多个别名），就像保险箱里能放好几把钥匙。但你自己用，一把就够了。

**最重要的警告**：keystore 文件 + 别名 + 密码，三个东西**永远别丢**。丢了这辈子再也签不出同一个签名的包了。备份到 U 盘或网盘。

<h2 id="ch3">3. 签名的流程：从代码到 APK</h2>

```
你写代码
   ↓
HBuilder 打包
   ↓
用你的 keystore 给 APK 签名（盖个章）
   ↓
生成带签名的 APK 文件
   ↓
发给我
   ↓
我安装时，Android 系统验章
   ↓
章对 → 安装成功 ✅
章错 → 拒绝安装 ❌
```

更新版本的流程：

```
旧版已安装
   ↓
你改代码 → 重新打包（同一个 keystore）→ 新版 APK
   ↓
我装新版
   ↓
系统检查：包名一样 + 签名一样 → 覆盖安装，数据全在 ✅
         包名或签名不一样 → 必须卸载重装，数据全丢 ❌
```

**覆盖安装的两个条件**：包名相同 + 签名相同。换了任何一个都不行。

<h2 id="ch4">4. 相关名词一锅端</h2>

### 加密相关

| 词 | 全称 | 解释 |
|------|------|------|
| **RSA** | Rivest-Shamir-Adleman | 一种老牌加密算法，2048 位的意思是破解它需要的算力 ≈ 让太阳烧到熄灭都算不完 |
| **SHA** | Secure Hash Algorithm | 给文件算一个"指纹"——改了一个字节，指纹全变。SHA1 是旧版（160 位），SHA256 是更安全的新版（256 位） |
| **SHA384** | SHA-384 | 你的证书用的签名算法，比 SHA256 更安全 |
| **PKCS12** | Public Key Cryptography Standards #12 | keystore 文件的格式标准，Android 和 Java 通用 |
| **自签名** | Self-signed | 你自己给自己盖章。大公司花钱找证书机构（CA）盖章，权威性更高；你自己用不用花钱，功能一模一样 |

### 打包相关

| 词 | 解释 |
|------|------|
| **包名** | App 的身份证号，格式像 `com.example.myapp`。同一包名 + 同一签名才能覆盖安装 |
| **测试证书** | HBuilder 默认用的公共证书，每个人打出来的签名都不一样，互相不认 |
| **自有证书** | 你自己用 keytool 生成的，一辈子不变 |
| **覆盖安装** | 不卸载旧版直接装新版，数据保留 |
| **云打包** | HBuilder 在云端帮你编译打包，不需要本地装 Android SDK |
| **离线打包** | 自己电脑上编译，需要装 Android Studio 和一堆 SDK |
| **H5+** | DCloud 的技术方案，把 HTML/JS/CSS 网页打包成原生 APK，同时提供 `plus.io`、`plus.share` 等调用手机能力的 API |

### 有效期

| 概念 | 解释 |
|------|------|
| **证书有效期** | 生成时设的，你的设了 36500 天（100 年），2126 年才过期 |
| **过期了怎么办** | 重新生成一个新证书——但签名变了，用户必须卸载重装。所以有效期越长越好 |

### 开发者中心

| 词 | 解释 |
|------|------|
| **DCloud 开发者中心** | HBuilder 的官网后台，管理你的 App 信息 |
| **SHA1/SHA256 指纹** | 你的证书的唯一标识。填到开发者中心，云打包时才不会弹警告 |
| **AppID** | HBuilder 给你每个项目分配的唯一 ID，比如 `H12345678` |
| **离线打包 Key** | 免费 20 个名额，每次改包名或 SHA1 占一个，同配置不重复占用 |

<h2 id="ch5">5. 实际操作：HBuilder 打包全流程</h2>

### 第一步：生成证书（一生一次）

确保电脑有 JDK（HBuilder 自带），打开 cmd，运行：

```
keytool -genkey -v -keystore "your-app.keystore" -alias myapp -keyalg RSA -keysize 2048 -validity 36500
```

这行干了什么：

- `-genkey`：我要生成密钥
- `-keystore`：生成的保险箱文件放哪
- `-alias pent`：钥匙名叫 pent
- `-keyalg RSA -keysize 2048`：用 RSA 算法，2048 位强度
- `-validity 36500`：有效期 36500 天（≈100 年）
- `-storepass / -keypass`：保险箱密码和钥匙密码（可以一样）
- `-dname`：证书上的名字信息

生成后得到一个 `.keystore` 文件。

### 第二步：配置 manifest.json

在 HBuilder 项目根目录的 `manifest.json` 里，找到 `"google"` 那段，填四行：

```json
"google": {
    "packagename": "com.example.myapp",
    "keystore": "your-app.keystore",
    "password": "你的密码",
    "aliasname": "myapp"
}
```

注意：`.keystore` 文件要和 `manifest.json` 放在同一个文件夹里。

### 第三步：开发者中心填 SHA

打开 [DCloud 开发者中心](https://dev.dcloud.net.cn/)，找到你的 App → Android 平台 → 填 SHA1 和 SHA256（用 keytool 命令查出来），包名填一致。

### 第四步：打包

HBuilder → 发行 → 原生 App 云打包 → 选"使用自有证书" → 选你的 keystore → 填密码 → 开始打包。

打完的 APK 就能直接装了。

### 第五步：更新版本

改代码 → 重新打包（同一个 keystore）→ 新 APK → 发给用户 → 覆盖安装，数据不丢。

<h2 id="ch6">6. 常见问题</h2>

**Q：别人能用我的证书吗？**

只有拿到你的 keystore 文件 + 知道密码的人才行。这两个都别给别人。

**Q：丢了证书怎么办？**

没办法。重新生成一个新的，但新证书签出来的包和旧的不一样，用户必须卸载重装。所以**备份到 U 盘或网盘**。

**Q：为什么包名要加点？**

Android 的规定。格式是倒过来的网址风格：`com.你的ID.App名`。保证全球唯一。

**Q：测试包名和正式包名有区别吗？**

功能没区别。正式包名需要开发者中心录入信息，测试包名不用。自己用或小范围分享，测试包名就够了。

**Q：HBuilder 的云打包安全吗？**

你的 keystore 和密码会上传到 DCloud 服务器用来签名，签完就删。如果担心，可以本地离线打包，但要装 Android Studio，配置麻烦。

---

## 总结

一句话：**用 keytool 生成一个 keystore，填进 manifest.json，每次打包都用它。文件别丢了。**

就这么简单。
